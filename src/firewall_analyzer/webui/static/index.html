The problem

Rule bases decay quietly.

Nobody sets out to leave any → any open on a production edge. It arrives one change ticket at a time, and the only record that it happened is a spreadsheet nobody has read end to end since the migration.

01

Nobody reads 4,000 rules

A manual review samples. Sampling is exactly how the one rule that matters survives three audits in a row.

02

Disabled is not deleted

Rules get switched off, never removed, and quietly re-enabled during an incident. They still need to be in the inventory.

03

Findings without arithmetic

"High risk" convinces nobody. An engineer pushing back deserves the ports, the source, and the sum that produced the number.

04

Every vendor exports differently

FortiGate calls it PolicyID, Palo Alto calls it Name, and one inverts its enabled column. Normalising by hand invites mistakes.

How it works

Export, upload, read the findings.

No agent, no connector, no credentials against the firewall. The file you already pull for change management is the entire input.

Pick the platform

Choose the firewall the export came from first. That decides which columns are read — and lets the upload be checked against the exact fields that vendor requires, before anything runs.

Drop the export

CSV or Excel. Spreadsheets are converted server-side, multi-value cells are split, and every vendor's action vocabulary is flattened so accept, permit and pass all mean allow.

Work the findings

Twelve checks run across the rule base. Filter by severity or category, open any rule to see exactly what matched, and export the result as CSV, JSON or a report.

What it checks

Twelve checks, per rule and across the whole base.

Seven run against every rule. Five need the file as a whole — you cannot tell that a rule is shadowed, or that the cleanup rule is in the wrong place, by looking at it alone.

Critical

Cleartext protocols

Telnet, FTP, SMBv1, SNMP, POP3, rlogin and 12 more — matched on service name, port, alternate port and port ranges.

Critical

Remote management exposure

SSH, RDP, VNC, WinRM and remote-desktop apps reachable from an untrusted source, matched by App-ID or port.

Critical

Allowed threat feeds

Rules that permit traffic to known-malicious lists — Palo Alto EDLs, FortiGuard ISDB objects, external feeds.

Critical

Unlogged allow rules

An allow rule with logging off is traffic you cannot audit or investigate after the fact.

High

Overly permissive

any in source, destination, service, application or zone — plus subnets wider than a /16.

High

Shadowed rules

Rules that can never match because an earlier, broader rule already caught the traffic.

High

Missing cleanup rule

Whether a deny-any-any exists at all, and whether it is actually the last rule in the base.

Medium

Application risk

Applications scored 0–5 against 5,271 Palo Alto App-ID signatures, with category and technology.

Medium

Expired rules

Time-bound rules whose expiry date has already passed but which are still live.

Medium

Subnet overlaps

Ranges that contain, are contained by, or partially overlap another rule's — and the hidden access that creates.

Medium

Duplicates

Byte-identical rules carrying the same match criteria under a different name.

Low

Hygiene

Unused rules, rules untouched for over a year, and missing security-profile coverage.

Platforms

Five vendor schemas, plus anything with the right columns.

Column names are matched case- and separator-insensitively, then each vendor's quirks are corrected — including FortiGate's inverted enabled column.

Evidence, not adjectives

Every score shows its working.

A finding that cannot be defended in a room with the network team is not worth raising. Each one carries the rule, what matched, the recommendation, and the sum that produced the number.

●

The whole file stays visible

Disabled and excluded rules are kept in the inventory, so "why isn't this flagged?" has an answer on screen.

●

Filter to what you'll actually fix

Severity and category filters live in the URL, so a filtered view is a link you can send.

●

Export in the shape you need

CSV for the tracker, JSON for the pipeline, or a report you compose section by section.

●

Nothing leaves the machine

The analyzer runs locally against a file you already hold. No outbound calls, no tenant, no agent.
